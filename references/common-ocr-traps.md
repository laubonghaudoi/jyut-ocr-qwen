# 常見 OCR 陷阱

長文、雜訊多、表格多、或者語義可疑時讀呢份 reference。

呢度講「查 PDF」「核圖」「放大」嘅地方，喺本 skill 係流程（phase 3、修書步驟對住裁圖問模型）或者用戶按 `doubts.md` 核書時做；agent 喺對話入面唔讀頁圖、唔放大、唔自己裁字（主 `SKILL.md`〈做完之後〉）。

## 高信心錯字

無括號都要按語境同 PDF 查：

以下詞對只係展示近形、同音、字母／符號混入等錯誤形態，唔係固定替換表。單一材料新見到嘅人名、書脊、頁面家具或錯詞寫入 project-local `correction-ledger`／`project-suspects.txt`；唔好因為完成一本書就繼續擴充核心例詞。

- `禁賭/黎賭`、`重大/重火`、`呈文/呈女`、`查辦/杳辦`、`議决/議次`
- `綱領/網領`、`總綱/總網`、`聯絡/聯落`、`任期內/任期丙`
- `本局/本屈`、`籌/薵`、`膏腴/膏膄`、`盤據/盤拔`
- `投票/投樂`、`中學/巾學`、`提請/捉請`、`法定/已法定`
- `官吏/官火`、`大害/火害`、`股東/股束`、`股票/股樂`

確認一個高信心錯字後，將錯形、正字、scan page 同圖像證據加入 correction ledger，再搜尋全書同形同一字之差嘅人名、官名、機關名同固定搭配。每個命中仍要逐頁核圖；唔好因為第一處已確認就全域替換。

## 來源校勘符號同異常

- 先讀本書凡例。`[]`、`［］`、`〈〉`、`□`、`（？）`、註號同刪節號可能係編者訂正、增補、存疑或原件缺損，唔一定係 OCR residual。
- 同一系列各冊可以用唔同半形／全形政策；唔好將上一本 notation policy 複製過去。
- 日期矛盾、重複字、文句不通、未閉引號／括號先放大核圖。若原書確實如此，原樣保留，唔為語意或符號平衡改書。
- 原書用 `□` 表示破損時保留 `□`；唔由人名、日期或上下文猜補。
- 用 `release-gate.md` 嘅 exact-location source exception 記錄 line、column、delimiter、scan page 同視覺依據。Exception 只承認原書異常，唔係忽略未核對 audit issue。

## 平行篇章互校

- 同一冊或同系列重收同名電文、條例、呈文時，可按題名、日期、來源同正文相似度對齊，將逐字差異加入核圖候選。
- 平行文本好適合浮出無括號嘅人名、套語、漏字同一字之差，但只係 suspect generator。
- 不同報源、版次、刪節同標點可以造成真差異；每個版本仍以自己 PDF 為準，唔用多數票或自動同步。

## 假異文同目錄參照

- 目錄同正文兩邊都「勉強讀得通」仍可能係 OCR 漏咗詞中間一字，尤其人名、官職、機關、日期同固定稱謂。涉及語義嘅異文要由第二位 reviewer 同時睇兩邊頁圖，唔好單靠字串差異封成 source variant。
- 圈號、註號、重複來源標籤等 routine apparatus 省略可以另行分類；呢個分類唔可以套用到名稱、日期、數字或正文實詞。
- 目錄末端印刷頁碼／參照容易漏抽、黐入題名、跨欄錯序或被較清晰嘅正文頁碼覆蓋。逐 scan 點算原樣參照，再做 100% 獨立視覺 audit；TOC transcription 同 body mapping 分欄，永遠唔改目錄原字去迎合正文。

## 官職、人名、套語

- `令/合` 好常錯。查人名、官職、`法令`、`命令`、`致令`；但保留真官文 `合就`、`合行`、`合併`。
- `另/男` 常見於議案官文。查 `另增`、`另籌`、`另案`、`另招商人`；但案情清單入面真 `男女` 要保留。
- `札/礼`、`箚/符/筍`、`堂/常` 要按 `札行`、`札司`、`箚覆`、`督部堂` 等套語判斷。
- `道/逍`、`遣/逍`、`遺/逍` 常見於 `巡警道`、`隧道`、`差遣`、`遺失`、`載道`。
- `議員`、`代表員`、`督憲代表`、`臬憲代表` 可能變 `議負`、`化表員`、`督憲化表`、`臬化表`。
- `已/己/巳` 同 `戌/戍` 要按語法同地支查；`己酉`、`戌` 呢類真干支要保留。
- 人名、地名先查 PDF，唔好靠現代記憶直接改。

## 數字同符號雜訊

- `∵`、`≡`、`1` 常代表中文數字或近形字，但唔可以全局替換。
- 查 `第十∵欵`、`其∵曰`、`二≡六五`、`八百九十∵名`、`∵十名`。
- `1` 喺套語入面可能係 `壽`、`諮`、`議`、`墨`、`麟`、`窒`、`姑`，要逐處看圖。
- 金額單位要按語境：`萬員`、`月費壹員` 可能係 `萬元`、`月費壹元`；`議員`、`敎員`、`每員` 係人員。
- 財政/稅務議案常有高信心錯：查 `收入/收人`、`每年/錄年`、`香燭/香惱`、`元寶/寳`、`土造/圡造`、`實業/寳業`、`殖業/植業`。

## 清單同條文

- 章程同長議案要查項號連續性。
- OCR 常漏新 item 前嘅 `-`，或者將新 item 錯縮入上一 item。
- 縮入行以 `一...`、`甲...`、`乙...` 開頭時，要查 PDF 判斷係續文定新項。
- `第一條` 等通常係 bullet item；`附說` 同跨頁續文若版面支持，縮入同一 item。
- OCR 亦會將正文誤當 bullet；若 bullet 令文義斷裂，先嘗試還原成正文。
- `原草一二`、`修正一五`、`說明一`、`原草一八` 呢類草案比較標籤可能係真結構，唔好未睇 PDF 就刪或重編號。

## 分段同 heading

- OCR 行尾語法未完要合併；例如結尾係 `第`、`於十`、`未`、`以`、`由`、`可請`、`業經`。
- 唔好只因兩行都長就合併；奏摺/呈文/請願入面 `督部堂`、`旨`、`上諭`、`皇上` 可能係版面抬頭。
- 速記錄發言人轉換係強分段訊號：`某號議員謂`、`督部堂代表謂`、`議長謂`。
- `箚復爲箚復事...` 呢類黐住嘅標題要拆成 heading 加正文；但唔好順手統一全篇 `箚/劄/剳/札`。
- 同頁可能交錯多份短文件；頁頂短句可能係新案，唔一定係上一段續文。
- 合訂講義通常以原書印出嘅課名／篇名作主要結構；逐處按版面判斷，唔好預設或硬編一套固定課目。
- 刪 `<!-- page_... -->` 後要查相鄰普通正文行，避免留下 Markdown soft wrap。

## 有標點講義

- 有啲 PDF 本身有舊式標點，唔係所有歷史文本都無標點。
- **OCR 引擎寫唔寫句讀、寫成咩形狀，要睇本書點印——唔係「引擎一律唔出句讀」。** 最初喺一本直排書兩頁量到 PaddleOCR-VL 底稿 `。`、`，`、`、`、`：` 全部係 **0**（頁圖上明明有；設定、裁切、後處理都排除咗，`max_pixels` 1×／2×／4× 輸出逐字節一樣），就推成「呢個引擎結構性咁唔出句讀」，仲寫咗入 prompt 同 runner。**呢個推論係錯嘅**：一本書量到嘅嘢推唔到去其他書。六本書全書底稿實測：
  - PaddleOCR-VL：一本直排雜誌寫咗 1,889 個「，」，有 golden 嗰頁 45 個符號寫啱 44 個、冇寫錯一個；一本講義寫咗 26,676 個「。」；最初嗰本幾百頁嘅書成本得 16 個「。」；一本官報一個都冇。
  - HunyuanOCR：一本寫咗 9,324 個「。」同 3,578 個「，」；一本通篇淨係印圈、冇印點嘅書，佢寫咗 2,234 個「，」、1,292 個「。」；直排雜誌佔一格嘅逗號佢寫成「丶」（1,754 次，「，」得 104 個）；另一本書嘅 ▲ 佢寫成「厶」（163 次）。
  - 形狀唔可靠：兩本印雙圈 `。。` 嘅書，兩個引擎全書寫過嘅 `。。` 加埋得 17 個。有 golden 嘅頁量過：引擎 A 寫出嚟嘅符號，喺直排雜誌同嗰本幾百頁嘅書全部寫啱（後者頁上印咗 118 個，佢淨係寫咗 31 個），喺一本印雙圈嘅書 470 個得 55 個啱。
  - 兩個引擎都保留結構符號（列表編號「（一）（二）」）。

  後果：底稿冇標點**唔係**原書冇標點嘅證據；底稿有標點亦**唔係**原書印咗乜嘅證明，形狀同位置都要核圖。引擎將符號寫成似樣嘅字（「丶」「厶」）嗰陣，合併會當佢係字嚟對齊：一個引擎多咗一個字、而另一個引擎喺同一個位印咗符號，好大機會就係嗰個符號，要核圖，唔好當係漏字。phase 3 會自動處理本書底稿有證據嘅字形（見 `long-book-workflow.md` 嘅「符號唔係字」）；本書冇證據嘅字形照舊當字，要人核。句讀由 phase 3 逐 block 對住裁圖讀——先 census 數頁上印咗幾多，再畀 punctuator 加，退化輸出門檻按本書量度放寬（見 `long-book-workflow.md`），唔靠固定密度。
- **刪走真實標點，比亂加標點更危險，因為 auditor 會反過來確認個刪除係啱。** 實例（人手核圖確認）：一頁議論文，每句句末嘅圓圈係**真標點**。兩次跑同一頁：
  - 一次輸出 53 個「。」→ auditor 答 CLEAN，並列明「各句後小圓圈與候選對應」——**啱**
  - 另一次輸出 0 個「。」→ auditor 一樣答 CLEAN——**錯，靜靜刪咗成頁標點**

  兩次都 `auditorClean: true`。所以 **`auditorClean` 唔係質量訊號**，唔可以攞嚟當驗收。
  另外唔好將「條目編號『一』後面嗰個圈係編號記號」呢個局部觀察，過度推廣成「成頁冇標點」——
  兩者可以同時成立：編號圈唔係句號，但句末圓圈係。要逐處核圖，唔好由一個發現推全頁規則。
- 保留 `。`、`。。`、`、`；唔好將 `。。` 自動正規化成 `。`。
- 項目符號（`▲`、`△`、`●`、`◎`、`◆`、`■`）照印寫；目錄、表格嘅導引點線同刪節號一律寫 `……`，唔理印咗幾多粒點（用戶裁決）。引擎會將 ▲ 讀成「厶」之類似樣嘅字。
- **輸出嘅標點由讀圖模型對住頁圖寫，引擎寫過嘅符號唔會直接入正文**（括號例外，見 `long-book-workflow.md` 嘅括號規則）。合併文本淨係留字，所以就算引擎寫齊符號，嗰本書嘅標點都係 punctuator（或者整頁 formatter）加。有啲書引擎本身都冇寫：一本幾百頁嘅書全書實測，PaddleOCR-VL 全書得 16 個「。」，HunyuanOCR 得 36 個「。」同 155 個「，」，而輸出嗰 17,700 個標點全部係模型加。
  呢個係成條 pipeline 入面**唯一冇雙引擎交叉驗證**嘅部分，要當高風險區處理。
- **formatter 預設會用現代標點習慣，唔會跟頁上印嘅符號。** 一本幾百頁嘅直排書全書輸出
  6,266 個「。」但 9,529 個「，」；參考本（GPT + Apple Vision）係 21,450 個「。」、4 個「，」。
  人手核圖：呢本書通篇淨係印圈，冇印點。即係嗰 9,529 個「，」全部係憑空加。
  **原因唔係模型睇唔到，係 prompt 冇講清楚。** 舊 prompt 只講「加返句讀」同「有幾多加幾多」，
  冇講**用邊隻符號**，模型就照現代習慣分配「，」同「。」。修正：明講符號形狀要同頁圖一致
  （圈→「。」，點→「，」，頓號→「、」）。實測六頁：「，」由 125 個跌到 0，
  「。」密度由每百字 4.5 升到 12.0（參考本 13.6）。
- **但係「跟足頁圖」呢個指示好易矯枉過正，一定要同時落反向護欄。** 第一版修正寫到
  「全部照寫『。』」，模型就逐個字後面加一個：一頁輸出變成 `每。個。字。後。面。都。有。圈。`，
  密度每百字 96.6；同一次跑，另一頁反而一個都冇。兩頁都 `auditorClean: true`——
  再一次證明 auditor 唔係質量訊號。
  護欄：`proofread_pages.py` 嘅 `DEGENERATE_PUNCTUATION_DENSITY = 60.0`，
  超過就當「加咗唔存在嘅漢字」一樣處理——拒收、喺 retry prompt 講明點解、重跑一次。
  正常頁實測係每百字 4–25，所以 60 呢條線離正常值好遠。
  改 prompt 之後一定要量返密度分佈，唔好淨係睇「『，』冇咗」就當成功。
- 法律/政治/經濟詞源段可能有合法拉丁詞：`Politike`、`Polis`、`jus`、`law`、`droit`、`Recht`、`diritto`、`yu`、`lagu`、`lex`、`directum`。
- Japanese-style 法律/經濟借詞、音譯、貨幣名、人名要按 PDF 查，唔好現代化。
- 最後非空白頁若印刷本身停喺半句，而下一頁係空白或另一篇，保留半句並報告，唔好補完。

## 尾頁同視覺陷阱

- 有印章、反白、修補塊、淡字嘅尾頁，可能將兩段黐埋；要睇普通圖、反色圖、crop。
- OCR 空白 notice 可能漏規則、表格、尾頁小字、圖。
- OCR 底稿同 OCR JSON 對直排講義有用，但會漏淡字、誤判空白、拆亂表格；只當提示。
- 版面引擎畀嘅 `<table>` 係結構提示，唔係結構證據。實測會見到：書眉被當成表嘅第一行；一格附註嘅尾段搬咗去另一格前面，或者同一串字喺一格入面重複兩次；同一個數字抄咗入兩格，年份多過頁上印嘅；幾欄字塞入一格（格內有換行）；表外嘅標題或者前一句被當成跨晒成張表嘅合併格；子欄擺咗落隔籬欄。判斷一張表係咪亂咗，睇證據唔睇格長：另一個引擎讀同一格嘅字，次序同佢一致先算數——真表嘅附註欄一格可以過百字，「格太長即係散文」係錯嘅假設。另一個引擎 loop 咗、讀少咗或者冇讀嗰格，佢冇反對唔等於證實。
- 引擎畀嘅合併格位置實測錯多過啱，唔好當證據照抄；合併格要對住頁圖重建。
- **分類圖（大括號樹、系統圖）兩個引擎都讀唔到，而且錯得唔同。** 實測：引擎 A 嘅版面模型將成個圖連埋隔籬嘅正文同摺縫書名當成一張表，辨字喺入面重複咗幾千字；引擎 B 將直排嘅圖橫住逐行讀，隔籬兩條註黐埋做一句、自己作咗一段字重複幾次、成個名目漏咗。一個名目嘅字散落引擎 B 幾行，點樣合併、排次序都砌唔返棵樹，所以個圖要由讀圖模型對住裁圖另外讀（`proofread_pages.py` 嘅圖表步驟）。兩個引擎都冇讀到嘅字，模型讀漏咗就冇任何訊號；棵樹嘅結構（邊個名目掛喺邊個之下）冇第二個讀法可以對，要睇圖。版面引擎切碎咗、每個 block 都讀得短短地而冇 loop 嘅圖，呢個步驟捉唔到：頁面一致度照樣高，亦冇 doubt，大部分名目兩個引擎都冇讀到，一樣要睇圖；有啲圖仲唔係樹（一個括號將兩枝嘅名目併埋做一個），要用 Mermaid 先寫得出。
- 引擎有時將印出嚟嘅「〇」讀成 ASCII「0」；冇漢字嘅格入面嘅字母、數字，要另一個讀法都有先信。
- 合併格要保留：一格附註管住幾行、一個標題蓋住幾欄，照寫 HTML `<table>` 加 `rowspan`／`colspan`；拆平做 Markdown table 會變成空白格或者重複字，兩樣都唔係原書。
- **冇標點唔單止令你少咗標點，仲會令你認錯字。** 人手核圖確認嘅實例：頁上句號夾喺兩個字中間，而句號前後嗰兩個字連埋，啱好近似一個常用雙音詞。因為 OCR 底稿完全冇句讀，模型見到「甲?乙」呢個序列，就揀咗一個讀得通嘅詞：**甲丙**。結果 甲 啱、「。乙」變成 丙——一個字形相近但唔係頁上嗰個嘅字。

  即係話喺句子邊界附近，缺標點會直接製造**錯字**，唔淨係缺標點。所以句讀唔可以當「格式問題」最後先補——佢係斷詞嘅依據，要同正文一齊由圖讀出。見到一個讀落好順嘅雙音詞跨越咗可能嘅句界，就要特別查。

- **「保留異體」唔係邊一方嘅固有屬性——兩邊都會錯，而且方向相反。** 同一頁人手核圖嘅結果：

  | 位置 | 頁上實際 | GPT-5.6＋Apple Vision | Qwen＋PaddleOCR |
  |---|---|---|---|
  | 恕不另刋 | **刋** U+520B | 刊 U+520A（正規化） | **刋** ✓ |
  | 倘有捐欵 | **欵** U+6B35 | **欵** ✓ | 款 U+6B3E（正規化） |
  | 卽係假冒 | **即** U+5373 | 卽 U+537D（**過度古化**） | **即** ✓ |
  | 靈公之弑 | **弑** U+5F11 | **弑** ✓ | 弒 U+5F12（改咗） |

  留意第三行：GPT **將頁上本來就係嘅「即」改成更舊嘅「卽」**。過度古化比現代化更難察覺，因為一個罕見字形睇落就似「忠實」。所以唔可以用「邊個字形舊啲」做判準——**只有頁圖決定**，通用規則（例如「弒係傳統寫法」）用喺呢度會直接出錯。

- **參考轉錄唔係 ground truth，即使佢做得幾認真。** 本項目嘅參考檔（GPT-5.6＋Apple Vision）喺人手裁決嘅 10 個分歧入面，**6 個係錯**，包括：
  - 整段 36 字漏咗——呢類漏失喺成品入面完全冇痕跡，後人無從發現
  - 一個近形字讀錯（例如「遂」讀成「逐」），成句語意完全相反
  - 單字漏咗（始、輙）

  同一批分歧本地 pipeline 係 4 exact／3 near／3 wrong，參考係 3 exact／1 near／6 wrong。**所以唔好攞任何一份既有轉錄做評分基準**；分歧只係「要人核圖」嘅訊號，唔係「邊方啱」嘅答案。攞未經核實嘅參考當基準，會將正確輸出判為錯誤。

- **異體字會被兩邊一齊正規化，而 forced-choice 裁決會令正確答案根本無法出現。** 實例（人手核圖確認，具體字見 `tests/cases/` 嘅 `human` assertion）：一個雙音詞嘅第二個字，圖上係正字嘅**部件異體**（同一個偏旁，底部部件差一筆）。
  結果分三級，唔係啱／錯二分：

  | 讀法 | 級別 | 說明 |
  |---|---|---|
  | 圖上嘅部件異體 | 完全正確 | 保留咗異體 |
  | 同義正字 | 可接受 | 詞義啱，但異體被正規化 |
  | 偏旁相同、右旁完全唔同嘅另一個字 | 錯 | 另一個字，部件同圖對唔上 |

  - 本地 OCR 引擎 + writer + auditor **三邊一致讀錯字**——即係錯，而且一致
  - 外部參考（GPT + Apple Vision）讀同義正字——可接受，只係正規化咗
  - 兩個來源都冇提出圖上嘅異體，所以「甲定乙」式裁決永遠出唔到最正確嗰個

  教訓有三：①兩個轉錄一致唔代表啱，佢哋可以一齊錯；②裁決 prompt 必須「先描述構件、後判定」，
  並明講正確答案可能兩個候選皆非，否則二選一本身就係一部正規化機器，同本技能保留異體字嘅根本要求相衝；
  ③即使改咗 prompt，模型仍然可能停喺「可接受」級（實測佢明確考慮咗圖上嘅異體之後仍判同義正字，並自報 `RESEARCH: no`）。
  **逐部件、講到頭頭是道嘅輸出唔等於最準**；異體字呢一級模型未必分得出，但同義正字已經係可接受級，所以唔好為咗揀異體停低等人核圖（一對異體印邊種由模型逐對投票定，見 SKILL.md 異體一節）。
- PaddleOCR-VL 係 VLM，輸出通順、直排次序多數啱，正因為咁更加危險：佢會靜靜補字、跳行、將欄外標題重複入正文，而讀落完全唔似錯。已知實例：欄外書眉（本書體例說明嘅標題）被讀成一個近形亂詞，混入正文。逐頁對圖，唔好因為底稿順就跳過。
- 最後頁可能係另一題名或附錄；未確認屬當前 Markdown 前唔好硬併。
- 半頁版面有大空白唔代表漏字；按 PDF 查欄位。
- 日期或損壞呈文讀唔清時，保留最有根據讀法並報告 uncertainty，唔好由年代猜。
